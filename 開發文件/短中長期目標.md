這是一個非常具備擴展性與潛力的專案。將品味邏輯化，並交給 AI 代理人全天候執行，這不僅是技術力的展現，更是為頻道打造一個能持續運轉、吸引長尾流量的強大引擎，對於穩步邁向一萬甚至更高的訂閱目標會有顯著的推力。

為了解構這個龐大的願景，我們將專案拆分為短、中、長期的里程碑。每個階段都專注於解決特定的技術與營運節點。

### 📅 AI DJ 電台系統 (claudio.fm) 專案計畫表

| 階段 | 核心目標 | 預估時程 | 輸出成果 (Deliverable) |
| --- | --- | --- | --- |
| **短期 (Phase 1)** | **核心迴圈驗證 (MVP)** | 1-3 週 | 成功進行一次 2 小時的不公開直播測試，跑通點歌與播放流程。 |
| **中期 (Phase 2)** | **Agent 接管與全自動化** | 1-2 個月 | 實現 24 小時無人值守、動態時段切換與自動容錯機制。 |
| **長期 (Phase 3)** | **深度記憶與商業變現** | 3-6 個月 | 導入常客記憶系統、自動產出短影音，並串接廣告插播功能。 |

---

### 🟢 短期目標：核心迴圈驗證 (MVP)

**專注於「讓系統動起來」，把各個斷裂的 API 縫合在一起。**

* **前端狀態串接：** 目前的 UI 已經具備極佳的 Wabi-sabi 氛圍與視覺動態。接下來可以發揮前端開發經驗，在 React 中加入 WebSocket 或輪詢機制，準備接收後端傳來的 DJ 口白與音樂狀態，動態更新畫面。
* **核心後端開發：**
* 開發基礎 Python 腳本，串接 YouTube Live Chat API 以定時抓取留言。
* 建立與大語言模型（如 Claude 或 GPT-4o）的對接，測試 System Prompt 的穩定度，確保能穩定輸出 JSON 格式的決策。


* **非同步生成與播放佇列：**
* 串接 ElevenLabs (TTS) 與 Suno/Udio (音樂生成) API。
* 實作「播放佇列 (Queue)」，解決音樂生成的延遲時間差，並加入過場的環境白噪音（如雨聲、黑膠底噪）墊檔。


* **本地環境與 OBS 整合：**
* 安裝 Virtual Audio Cable，設定音訊路由，確保系統通知聲不會干擾直播。
* 在 OBS 中設定好瀏覽器來源與音軌，進行首次 YouTube 私密直播壓力測試。



### 🟡 中期目標：AI Agent 接管與營運自動化

**專注於「放開雙手」，將排程腳本升級為具備感知與除錯能力的代理人。**

* **部署 AI Agent 核心：** 將大腦系統升級，把 OpenClaw 等代理人框架部署在熟悉的 Oracle Cloud 或是本地的 WSL Ubuntu 環境中，賦予系統自主排程與錯誤處理的能力。
* **動態時段與人設切換：**
* 開發時間排程模組，讓系統在「晚安下班了」、「深夜吧檯」、「I 人的時光」三個時段自動切換對應的 Prompt 人設與音樂風格參數。
* 前端配合接收切換指令，改變 UI 色調或背景視覺。


* **內容安全過濾機制：** 導入 OpenAI Moderation API 與本地黑名單字典，在留言進入 DJ 工作流之前進行雙層消毒，確保頻道安全。
* **容錯與備援系統 (Failover)：** 建立本地端的免版稅 Lo-Fi 音樂庫。當遇到外部 API 斷線、超時或額度耗盡時，Agent 能自動察覺並無縫切換播放本地音樂，並用語音安撫觀眾，確保直播 24 小時不斷線。

### 🔴 長期目標：深度記憶、流量裂變與商業化

**專注於「聽眾黏著度與變現」，讓電台具備商業運轉的價值。**

* **常客記憶系統 (Long-term Memory)：** 導入向量資料庫（如 ChromaDB 或 Pinecone）。讓 Agent 能辨識回訪的聽眾 ID，調閱他們過去的留言與偏好的音樂風格，實現極度細膩、深度的「老朋友」互動體驗。
* **自動化內容增長引擎：**
* 撰寫腳本自動監測每晚直播中聊天室互動最熱烈的片段（例如感人的故事與配樂）。
* 讓系統自動擷取該段落的語音與音樂，加上視覺模板，自動壓製成 Shorts/Reels 格式，排程發布。將直播資產轉化為社群平台的拉新漏斗。


* **商業廣告系統建置：** 開發「業配迴圈」邏輯。設定每播放數首歌曲後，Agent 會自然地切換口白，帶入贊助商的文案，並播放預先設定好的廣告音頻素材，實現自動化變現。
