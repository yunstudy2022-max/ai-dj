# Phase 2 — 后端核心引擎开发

## 📋 任务概述
将 claudio.fm 从"美观的 UI"升级为"能自动运转的电台"。

实现 Python 后端，能实时：
1. 抓取 YouTube 聊天室留言
2. 分析观众情绪
3. 生成 DJ 语音和背景音乐
4. 推送更新到前端 UI

## 🏗️ 子任务清单

### Task 2.1 — YouTube Live Chat API 集成
**目标**：实时抓取直播聊天室消息
- [ ] 配置 YouTube Data API 凭证
- [ ] 实现 `YouTubeChatFetcher` 类
- [ ] 设置定时轮询机制（每 5 秒抓取一次）
- [ ] 测试消息抓取准确性

**脚本位置**：`scripts/youtube-chat-fetcher.py`
**预期输出**：
```json
[
  {
    "author": "yuki_03",
    "text": "今晚加班好累",
    "timestamp": "2026-05-11 23:45:30"
  }
]
```

### Task 2.2 — 情绪分析引擎
**目标**：分析留言情绪，选择合适的 DJ 回应
- [ ] 集成 Claude 3.5 Sonnet API
- [ ] 设计情绪分析 Prompt
- [ ] 实现情绪分类器（sad/happy/neutral/introspective）
- [ ] 构建聊天室整体氛围分析

**输入**：最近 12 条留言
**输出**：
```json
{
  "overall_mood": "melancholic",
  "dominant_emotion": "tired",
  "confidence": 0.87,
  "keywords": ["work", "sleep", "lonely"]
}
```

### Task 2.3 — DJ 文案生成
**目标**：自动生成温暖的 DJ 台词
- [ ] 设计 DJ Prompt（融入三个时段人设）
- [ ] 实现时段检测（自动选择人设）
- [ ] 让 Claude 生成 30-50 字的回应
- [ ] 添加个性化定制（提及听众名字等）

**输出例**：
```
有时候，靜靜聽著就夠了。Yuki，看你加班这么辛苦，这首曲子就献给今晚还醒著的你。
```

### Task 2.4 — 音乐生成提示词构建
**目标**：根据情绪自动生成音乐参数
- [ ] 设计情绪 → 音乐参数的映射表
- [ ] 实现 Suno API 提示词生成
- [ ] 测试不同情绪下的音乐质量
- [ ] 建立音乐缓存机制（避免重复生成相同风格）

**输出例**：
```
"Lo-Fi hip hop, melancholic piano, vinyl crackle, slow drums, 
 introspective mood, no vocals, 68 bpm"
```

### Task 2.5 — 非同步处理队列
**目标**：解决 API 延迟问题
- [ ] 实现异步消息队列
- [ ] 设计播放缓冲机制
- [ ] 在等待音乐生成时播放环境音或备用音乐
- [ ] 防止直播中出现长时间的"死寂"

**架构**：
```
T=0s     DJ开始讲话
T=2s     后台已发送音乐生成请求
T=5s     DJ讲完了，但音乐还没生成
T=5-60s  播放雨声/翻书声等过场音乐
T=60s    音乐生成完毕，无缝切换播放
```

### Task 2.6 — OBS WebSocket 集成
**目标**：能自动控制 OBS 推流
- [ ] 配置 OBS WebSocket 插件
- [ ] 实现推流启停控制
- [ ] 同步虚拟音轨设置
- [ ] 测试多次启停的稳定性

### Task 2.7 — 本地 2 小时压力测试
**目标**：验证系统稳定性
- [ ] 建立私密 YouTube 直播
- [ ] 启动完整的 claudio.fm 系统
- [ ] 运行 2 小时，监控：
  - 内存泄漏情况
  - API 调用成功率
  - 音频同步状态
  - 前端 UI 响应性
- [ ] 记录所有错误和改进建议
